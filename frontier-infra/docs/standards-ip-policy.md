# Standards IP policy notes

This is an implementation and marketplace-readiness note, not legal advice.

## Copyright

The plugin is MIT-licensed as original Frontier Infra material. It does not
vendor upstream project source code. If future releases copy substantial
upstream code, docs, examples, or assets, include the full upstream notices in
`THIRD_PARTY_NOTICES.md` and keep the public source allowlist audit with the
release record.

## Trademarks and conformance marks

Keep copyright licensing separate from marks and conformance labels. A public
release should define who may use Frontier Infra marks, which tests support a
claim, and how stale or unsupported claims are corrected.

## Patent posture

MIT does not include an express patent grant. If Frontier Infra is intended to
operate as an open standard rather than only a permissive code/doc release, the
publisher should choose a documented patent posture before public marketplace
submission. Options include an explicit patent non-assert, a royalty-free
standards policy, or using a license with an express patent grant for future
reference implementations. Do not relicense existing contributions without the
needed rights-holder authorization.

## Publisher identity

Before public marketplace submission, align the verified publisher identity,
domain, support address, privacy policy, terms, repository ownership, and any
mark policy. Do not represent draft policy text as attorney-approved.
